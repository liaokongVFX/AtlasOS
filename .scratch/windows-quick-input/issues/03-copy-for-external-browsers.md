# 03: 在外部 Edge 和 Chrome 显式复制片段

**What to build:** 用户从 Windows 桌面版 Edge 或 Chrome 的网页输入框按片段快捷键后，看到对应片段的「复制片段」操作。通过快捷输入窗口选择片段时也保留选择并提供复制。用户自行决定是否复制以及向哪里粘贴。

**Blocked by:** 01 在记事本原位置插入一条固定片段

**Status:** resolved

- [x] 在真实 Edge 和 Chrome 的网页输入框分别验证片段直达和窗口确认。两种入口均显示所选片段和复制操作，页面中原输入框以及另一输入框的内容均保持原样。
- [x] 打开提示、取消提示或主动切走后，剪贴板内容及其格式保持原样。回车确认搜索选择或按住片段键均不会被视为同意复制。
- [x] 明确点击「复制片段」后，可将中文、表情、缩进、制表符、连续空行和末尾换行按原样粘贴到多行网页编辑区。
- [x] 在两个浏览器的独立测试配置中记录实际结果。外部浏览器的复制策略不影响记事本及 AtlasOS 内嵌网页的原目标插入行为。

## Windows 验收记录

- 在受看门狗保护的独立桌面上，分别用全新配置启动 Chrome 158.0.8127.36、Edge 158.0.4370.33 和 AtlasOS。两个浏览器均通过网页输入框的真实系统热键直达，以及窗口键、方向键选中第二条片段、Enter 确认。两种入口均显示该片段名称和复制按钮。Esc 或切到另一应用均关闭提示，两个网页字段和剪贴板序列号保持原值。
- 按住片段键期间切到记事本，再松开按键，曾导致提示抢回焦点。修复后两个浏览器均将焦点留在记事本，未改动页面及剪贴板。浏览器进程名下的标准 Win32 Edit 也经本地控件夹具验证，只提供复制。
- 在具有独立剪贴板的非交互窗口站复验。该站由测试夹具调用系统快捷键的回调，使用实际搜索窗口和两个独立浏览器配置。提示出现、额外的 Enter、Esc 和主动切窗后，纯文本、HTML、RTF、图片、格式列表及序列号均保持原值。点击复制按钮后，分别向两个浏览器的多行文本框发送 Ctrl+V，粘贴结果与保存正文逐字符一致，另一字段保持原样。正文含中文、表情、缩进、制表符、连续空行、行尾空格及末尾换行。
- 记事本原选区插入和一次撤销通过。AtlasOS 内嵌网页通过直达和窗口确认的光标居中、选区替换四种组合，重复运行三次通过。切换网页输入框、切换标签、替换元素和导航均阻止旧请求写入。
- 合入搜索窗口版本 `e9bfa77` 后，生产构建以及 14 项搜索和热键测试通过，独立剪贴板的两个浏览器用例均复验通过。本地测试入口为 `tests/browser-copy/native.test.py`、`tests/browser-copy/isolated.py` 和 `tests/atlas-editor/run.ps1`。
